## WOLV validation observations

- `services/browserTradeQuote.ts` requires quote UUID, chain `56`, RFQ mode, token pair, token decimal strings, and integer smallest-unit quote amounts; it normalizes using provider decimal metadata and applies local reference-price/threshold checks. This is consistent with the pinned quote model, but still has no genuine response compatibility evidence.
- `lib/binanceExecutionValidation.ts` rejects all SWAP and RFQ payloads. This is fail-closed behavior, **not** verified compatibility.
- `services/browserTradeExecutionBoundary.ts` checks durable intent, wallet, quote binding, parameters, and expiry before rejecting unsupported execution. That validates WOLV intent integrity, not provider payload semantics.
- `validateApprovalTransaction` decodes standard ERC-20 `approve`, binds spender to quote and reviewed trusted spender list, and requires exact amount (or an allowed zero-reset). It does not validate the swap transaction itself.
- `services/bawQuote.ts` derives a local quote ID/expiry and binding, expects `slippage` to equal the requested percentage divided by 100, computes a price from amount strings, and requires token decimals/reference data. The BAW source does not establish output slippage scaling or output amount units. This remains an assumption in the adapter's expected provider response contract.
- `services/bawAsset.ts` resolves through `parseRwaAssetRecords`; that parser does not populate decimals. The production resolver therefore cannot satisfy `getBawQuote`'s required decimal field using the current asset record, so this path rejects before requesting a CLI quote. Do not infer decimals from the Binance Web3 aggregator contract.
- `services/bawExecution.ts` leaves a `FINISHED` order as `FINISHED_UNVERIFIED` and retains any reported output quantity, because BAW documentation does not establish its unit or an independent settlement check.

No application code was changed. No BAW command, provider API quote, wallet signing, approval, swap, RFQ submission, or transaction-status RPC request was made. No production configuration or database was inspected or modified.
